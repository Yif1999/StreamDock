# 设计规范

StreamDock 的视觉与交互规范：控台按键、灯光、桌面界面。新增模块、页面或场景时按此执行；要改规则，先改这里。
实现见 `DockCore/KeyDesign.swift`（按键）、`DockCore/LightEngine.swift` 与 `ControlModules/GlowLevels.swift`（灯光）。

## 总则

1. **一致优先**：同一种含义只有一种表现；所有按键共用一个网格、一套颜色、一种按下反馈。
2. **颜色只表示状态**：模块不能自选颜色，只能声明状态，颜色由设计系统统一决定。装饰性颜色一律不用。
3. **为像素设计**：控台按键是 64×64、1:1 点对点显示，所有尺寸、位置以整像素为单位。
4. **成体系，不打补丁**：遇到问题先找规则层面的原因，改规则而不是单点修补；改完写进本文件。
5. **所有变化都要过渡**：灯光不允许瞬间切换（见"灯光"）。

## 控台按键

### 画布

- 按键图 64×64 JPEG，在 480×272 的屏上 1:1 显示，图外是一圈黑色窗口（2026-10-24 用 1 像素棋盘格实拍确认）。
- 屏幕能看到 RGB 子像素：1 像素宽的线会带彩边，图形线条不细于 2 像素。

### 内容

每个按键只有这几样东西：**图标**（SF Symbols）或**数值**（数字或短词）、可选的**标签**，或者**整幅封面**。
模块用 `KeyFace` 描述：`symbol` / `title`（数值）/ `caption`（标签）/ `artwork` / `tone`。

### 网格

| 项 | 规格 |
|---|---|
| 底色 | 纯黑 `#000000` |
| 边距 | 四周 8 px |
| 标签 | 系统字体 Medium 11 px，字距 +0.5 px，基线固定在 y = 55（所有按键一致，Latin 与 CJK 同基线），宽度上限 56 px，超出自动缩小 |
| 图标框 | 无标签 36×36，有标签 28×28；外框尺寸与位置取整像素 |
| 数值 | SF Rounded Semibold 23 px，字距 −0.3 px，宽度上限 50 px |
| 图标 / 数值与标签间距 | ≥ 6 px |
| 垂直位置 | 按实际笔画（不是字体框）定位：无标签时在边距内居中；有标签时与标签成组，剩余高度按 3:1 分在上、下 |

### 状态与颜色（`KeyTone`）

| 状态 | 用途 | 底色 | 图标 / 数值 | 标签 |
|---|---|---|---|---|
| `normal` | 普通操作 | 黑 | 白 `#FFFFFF` | 灰 `#8E8E93` |
| `dim` | 当前不可用 | 黑 | 深灰 `#4A4A4E` | `#3E3E42` |
| `on` | 开关处于开启（设备开、当前场景、已喜爱、显示中的来源） | 白 | 黑 | `#3A3A3C` |
| `alert` | 录制中、已静音、危险操作 | 红 `#FF3B30` | 白 | `#FFD7D4` |
| `live` | 推流中 | 绿 `#30D158` | 黑 | `#0B3D1A` |
| `caution` | 等用户继续（录制暂停、工作室预览） | 琥珀 `#FF9F0A` | 黑 | `#4A2C00` |

- 状态底色**铺满整键，无圆角**。
- 红、绿、琥珀与灯带含义一致：录制红、推流绿、暂停琥珀。

### 额度键（`KeyMeter`）

服务额度用整键作进度条，是"颜色只表示状态"之外唯一的例外：颜色代表服务本身，不代表状态。

- **填充表示剩余**：从左往右按剩余比例填满整列像素（`round(剩余 × 64)` 列，边缘不做混色）；用完就是全黑。数值显示剩余百分比（`83%`），标签说明窗口（`5h`、`Week`）。
- **服务色**：取各自应用图标的主色——Claude `#E4643F`、Codex `#576EFE`（2026-10-25 从图标取样）。只用在填充上。M18 屏幕会把颜色洗淡，柔和的品牌色（如 `#D97757`）在控台上发灰，所以用图标里饱和的那一档。
- **文字随底色分色**：同一个数值或标签被填充边缘切开时，填充上的部分用黑色（标签用服务色压暗到 35%），黑底上的部分照常用白色（标签灰色）。按列裁切，像素级对齐。
- 额度键不叠加状态色；没有数据时显示 `—` 和 `dim` 状态。
- **打开应用的键也铺满整键**，不在键里放带圆角的图标：把图标上的图形抠出来（与图标底板颜色差距足够大的像素，边缘按底板反混色），放大 1.2 倍铺在整键底色上（`IconGlyph`）。Claude 底色就是服务色 `#E4643F`、白色星芒；Codex 白底、蓝色云团（取 ChatGPT.app 包内的 `icon-codex-light.png`，因为 Codex 装在 ChatGPT.app 里，应用图标是 ChatGPT 的）。只读图标中间 68%，避开底板的圆角边和高光；颜色差门槛高于底板自身的上下渐变。

### 长按

- 不可逆或打断性的操作（息屏、PC 插座断电、退出 Apple Music）都要**按住 1 秒**，全部用同一个 `KeyHold`：
  - 键面不变（照常按下变暗），一条 3 px 的线从顶边中点出发、沿按键边缘顺时针走一圈，正好 1 秒走完即执行；匀速，不加缓动，让 1 秒读起来就是 1 秒。
  - 线离边缘 2 px，浅色键上线和黑色窗口之间留一圈原底色；线的颜色逐像素取黑或白中反差大的一个（深底白线、白色开启键和亮封面上黑线）。
  - 每秒重绘 60 帧，与按键屏幕刷新率一致，每帧正好显示一次刷新；帧按开始时刻排成固定时间格，某帧晚了不拖后面的帧。线头按比例部分绘制，走得平滑。
  - 带宽：一帧 JPEG 约 2.3–3.3 KB。控台收到图片不回任何确认，厂商库又先放进自己的队列再慢慢发，所以程序里测不出真实传输速度（曾用"关闭连接要等多久"估出 114 张/秒，实为关闭的固定耗时约 2 秒，已作废）。传输上限要用 `dock-probe fpstest --all` 从外面看，见下。
  - 屏幕实际刷新率要从外面看：`dock-probe fpstest [帧率…]` 在 1 号键上按给定帧率连续显示序号，用手机慢动作（240 帧/秒）拍下，逐帧数序号。序号连续说明跟得上，跳号时一秒内出现的序号数就是真实刷新率。
  - 实测（2026-10-25，慢动作视频按黄牌 2 秒换算为 120 帧/秒）：**按键屏幕约 60 Hz**。24 和 60 帧/秒时序号全部出现；60 帧/秒每个序号停留约 1/60 秒；114 帧/秒时只出现隔一个的序号，每个同样停留约 1/60 秒，多发的一半被丢掉。24 帧/秒时每个序号的停留时长不均匀（视频里 2–7 帧不等），因为 24 不能整除 60，只能交替显示 2 次和 3 次刷新。
  - **规则：按键动画的帧率必须整除 60**（60、30、20、15…），否则帧在屏幕上交替停留不同时长，看起来忽快忽慢。连续运动用 60；慢变化（闪烁、呼吸）可以用更低的整除帧率省带宽。
  - **多键同时动画**：实测（2026-10-25，`fpstest 60 --all`）15 个键各 60 帧连发 5 秒共 4500 张，END 牌晚约 2 秒才出现，整屏真实约 600–700 张/秒（约每键 43 帧）；超出部分在厂商库队列里积压，画面照样连续但越来越落后于实际时间。分配规则：帧率整除 60，且"同时在动的键数 × 帧率 ≤ 450 张/秒"（实测约三分之二，给灯带和偶发更新留余量）——1–7 个键 60 帧，8–15 个键 30 帧。同一次测试曾出现过一次控台断连重启、一次 END 迟迟不出现，原因未查明，超量发送不能当作安全。
  - **设计时默认按 60 帧做按键动画**（合成器场景会大量用到）。整屏 15 个键同时动画基本不会出现；真要出现时，由控制器统一按上面的规则降到 30 帧，不由各模块自行降帧。
  - 松手、翻页、切场景都取消，线立即消失。
  - 预览：`dock-probe holdsheet <out.png> [封面图]`。
- 同一个键既有短按又有长按时，短按动作在**松手**时执行，长按触发后松手不再执行短按。

### 按下

任何按键（包括封面）按下时**整键变暗 30%**，像 iOS 按钮被压下。不用提亮：提亮会让黑底变灰，对白色开启键也没有效果。

### 文案

- **标签用英文**：11 px 的中文笔画会糊在一起，英文清晰。
- 用短词，首字母大写，尽量不超过 10 个字符：`Volume` `Brightness` `Sleep` `Mic` `Muted` `Loved` `Record` `Recording` `Pause` `Resume` `Stream` `Live` `Studio` `Transition` `Replay` `Save` `Saved` `Camera`。
- 通用状态词：`On` / `Off` / `Offline` / `Unknown` / `Unset` / `Failed` / `Retry` / `…`（处理中）。
- 数值不带单位符号时由标签说明含义（`45` + `Volume`）；温度、百分比、功率保留符号（`26°`、`40%`、`86W`）。
- 功率：1000 W 以下取整瓦（`86W`），以上用 kW 保留一位小数（`1.5kW`）。
- 带功率计量的开关开启时，用读数代替图标（`on` 状态不变）；关闭或读数不可用时显示图标。
- 用户自己起的名字（HA 实体名、OBS 场景 / 来源名）原样显示，不做自动翻译；按键名称在设置里填英文短名，同一设备的按键用同一个名字（`A/C`、`Fan`、`Light Bar`、`PC`），由图标区分功能。设置窗口里有此提示。
- 错误详情放在设置窗口，按键上只显示 `Failed`。

### 渲染与编码

- 图标和文字以 4 倍分辨率绘制，精确缩小到 64×64，再提高边缘对比度去掉灰边。
- JPEG 质量 1.0（全色度）。低于 1.0 时 ImageIO 会做 4:2:0 色度子采样，彩色边缘糊成 2×2 色块。

### 新增按键检查

1. 选一个 SF Symbol（在 36 / 28 px 下仍能认出），或者用数值；
2. 声明状态（`KeyTone`），不要写颜色；
3. 标签按上面的文案规则；
4. 用 `dock-probe keysheet <out.png> [封面图]` 出预览，必要时 `--pressed` 看按下状态；
5. 在控台实物上确认。

### 试过但放弃

| 方案 | 结论 |
|---|---|
| 各模块各自强调色（青、黄、玫红、天蓝） | 五花八门，改为状态语义 |
| 深灰底 `#1C1C1E` | 在黑色窗口里显出灰方块 |
| 圆角状态底块 | 改为整键铺满 |
| 中文标签 | 11 px 糊，改英文 |
| 手绘矢量图标 | 纯直线图形略好，复杂图形不如系统图标，且不够锐利 |
| 开源像素图标库 pixelarticons | 像素风不好看，缺快进 / 快退等播放器图标 |
| 像素中文字体 | 改用英文后不需要 |
| 按下提亮 25% | 黑底变灰，白色开启键无反馈 |

## 灯光

细节与参数见 [rhythm.md](rhythm.md) 和 [progress.md](progress.md) 的"灯光最终规则"，原则如下：

- **一切变化都有缓动**，由灯光引擎统一保证，模块无法绕过。
- **感知亮度**：所有亮度在感知空间计算，最后只做一次 Gamma 2.2 映射；暗部有防抖。
- **场景各管各的灯**：灯带只显示当前场景的东西；别的场景的状态和提醒不会出现（例如 OBS 录制灯只在通用控制场景亮）。
- **优先级**（场景内）：通知 > 活动状态（OBS 输出）> 当前页动画（音乐）> 场景底色。
- **颜色语义与按键一致**：录制红 `#FF0000`、推流绿 `#00FF00`、暂停琥珀 `#FF9C00`。
- **灯带 60 Hz**：实测（2026-10-25，`dock-probe ledfps`，整条灯带每帧在全亮和全灭之间切换、慢动作拍摄）60 帧/秒切换正常，90 和 120 明显跟不上。灯光引擎和所有灯效（包括音乐律动）都按 60 帧、固定时间格出帧（`FrameGrid`，与按键动画共用）：某帧晚了不拖后面的帧，卡顿后跳到下一格、不连发补帧。灯效的动态一律按经过的时间计算，不按帧数，帧率变化不改变速度。
- **颜色代码在灯带上和屏幕上一致**：颜色先按 sRGB 解码成线性光再取灯珠比例（`LightPixel`），亮度另按感知亮度走伽马 2.2。2026-10-25 之前颜色代码被直接当成灯珠比例，小通道被放大几倍（含白色成分的颜色偏粉紫、橙色偏黄），当时对着灯带调出的颜色都已换算成新代码（`RGB.fromRawLEDProportions`，灯带上的样子不变；设置里保存的自定义场景色在升级后第一次启动时换算一次）。旧代码 → 新代码：VibeCoding `#85FC5E` → `#BEFCA2`，合成器 `#FF5700` → `#FF9E00`，OBS 暂停 `#FF5500` → `#FF9C00`，Codex 提醒 `#3048FF` → `#7891FF`，Claude 提醒 `#FF2400` → `#FF6900`；纯色不变。仍以灯带实物为准：灯珠的颜色和屏幕不会完全一样，新颜色还是要对着灯带确认。音乐律动一直走 OKLab，本来就是线性光，不受影响。
- **场景底色**（设置里可改）：

| 场景 | 默认色 | 灯带观感 |
|---|---|---|
| 通用控制 | `#FFFFFF` | 白 |
| VibeCoding | `#BEFCA2` | 黄绿（2026-10-25 用户在灯带上调定；与 Codex 蓝、Claude 橙拉开距离，灯带提醒用应用色） |
| 合成器 | `#FF9E00` | 橙（2026-10-25 用户在灯带上调定） |

- **音乐灯效追求柔和精致**（参照 HomePod 顶部灯光）：滤色叠加、临界阻尼包络、流光只加减速不换向、OKLab 混色。

### 编程助手提醒（VibeCoding，`AgentLight`）

Codex 和 Claude 的任务状态只做在灯带上，不占按键。2026-10-25 在灯带上逐条演示、按用户反馈定下：

- **颜色 = 是谁，动态 = 什么状态，亮度和速度 = 多急。** 状态不用另外的颜色，都用应用自己的灯带色：Codex `#7891FF`、Claude `#FF6900`（对着灯带调定）。场景底色黄绿 `#BEFCA2`，和两种应用色拉开距离。
- **三档强度**：强提醒（召唤；完成、出错那一刻）亮点满亮 1.0、灯环底光 0.4；环境（巡航）光点 0.8、底光 0.25；弱提醒（静候 0.7、故障保持 0.65、召唤弱版 0.7）。提醒灯效始终算活动状态，不被灯光引擎减半。
- **长亮不低于 0.25**：太暗时导光条不再把灯珠的光混开，一颗颗灯珠就显出来了。只有一闪而过的凹陷可以更暗。
- **不显颗粒**：灯带上移动的亮点至少覆盖约 3 颗灯：亮芯、前方约 1.6 颗灯的柔和边缘、后方逐渐变暗的长尾巴。
- **一切亮度变化都缓降缓升**，包括"故障"闪烁：它是两次平滑的凹陷，不是亮灭切换。生硬的亮灭在 60 Hz 下熄灭帧数忽多忽少，看起来像丢帧；不规则的间隔也被看成卡顿。亮点出现时从周围亮度淡入，不凭空跳亮。
- **强版和弱版是同一条曲线**：整个周期按比例划分（亮起、行进、汇合、间歇），弱版只是放慢、调暗，不含固定秒数（固定秒数曾让强版的光点跑到两侧才亮起、弱版先停住再走）。唯一的区别是弱版召唤不让短灯条跟着闪。
- **动态**：
  | 状态 | 名字 | 灯效 |
  |---|---|---|
  | 工作中 | 巡航 | 光点带长尾巴逆时针绕环，3 秒一圈，匀速 |
  | 完成那一刻 | 合拢 | 光点加速、尾巴拉长到铺满整圈，满亮一下，缓降到静候 |
  | 完成、等你查看 | 静候 | 整圈静止，6 秒一次很轻的呼吸 |
  | 出错那一刻 | 故障 | 光点停住并膨胀成满亮整圈，两次凹陷，缓降到故障保持 |
  | 出错、等你查看 | 故障保持 | 整圈常亮，每 1.5 秒同样的两次凹陷，像一盏快坏的灯 |
  | 等你批准或回答 | 召唤 | 两道光在前方正中（离人最近）亮起，以平均速度 0.6 倍的初速出发（亮足时只走出约 1.5 颗灯，不停顿），沿两侧加速，到后方减速汇合并亮一下，1.4 秒一次；短灯条在汇合时同步亮 |
  | 同上，但应用在前台 | 召唤弱版 | 同一条曲线放慢到 3 秒一次，更暗，短灯条不闪 |
  | 空闲、打断、你已查看 | — | 1.2 秒淡回场景底色；你主动打断时不放过场 |
- **你在看就不吵**：应用在前台时召唤降为弱版；完成时只放合拢，直接淡回底色。
- **状态只靠明确信号结束，不用超时**：长时间没有事件仍显示工作中。
- **两个应用同时有状态**（不分左右半圈）：
  - 都在工作：两颗光点同时绕环，相隔半圈，各用自己的颜色；尾巴缩短，两个亮区之间留出暗区，每颗灯按两颗光点各自贡献的亮度混色，换色只发生在暗区（在亮头上硬切换色会显得卡顿）。
  - 都在召唤：一次一个应用轮流，换色在汇合闪光淡去后的最后四分之一周期里渐变。
  - 都在等你查看（静候或故障保持）：每 3 秒换一个应用，1 秒渐变。
  - 级别不同：更急的占整个灯环，另一个应用用自己的颜色以 0.5 点亮两根短灯条。
  - 优先级：召唤 > 完成、出错那一刻 > 故障保持 > 静候 > 巡航 > 空闲。
- 演示：`dock-probe agentlight [codex|claude|both] [步骤…]`，按一个应用（或两个应用同时）的完整故事逐步播放并念出场景；`--sheet <out.png>` 离线出图。`dock-probe ledbench` 检查灯带是否丢帧（2026-10-25 实测 60 帧下 0 丢帧）。

## 桌面界面

- 菜单栏面板与设置窗口：macOS 26 原生液态玻璃控件；玻璃只用于控件层，不叠在内容上。
- 当前场景用其灯条颜色轻微着色，与控台、灯带的颜色关系一致。
- 界面文字为中文。

## 工具

- `dock-probe keysheet <out.png> [封面图] [--pressed]`：通用控制三页和 VibeCoding 额度页的按键预览（像素放大 3 倍）。
- `dock-probe holdsheet <out.png> [封面图]`：三种长按键在按住 0、¼、½、¾、满时的描线。
- `dock-probe keytest [秒数]`：第一排显示像素测试图（条纹、棋盘格、边框），检查 1:1 显示。
- `CPA_KEY=… dock-probe cpa <地址>`：只读查看 CPA 的账号列表和 Claude / Codex 额度接口的原始返回（邮箱打码）。

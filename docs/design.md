# 设计规范

StreamDock 的视觉与交互规范：控台按键、灯光、桌面界面。新增模块、页面或场景时按此执行；要改规则，先改这里。
实现见 `DockCore/KeyDesign.swift`（按键）、`DockCore/LightEngine.swift` 与 `ControlModules/GlowLevels.swift`（灯光）。

## 总则

1. **一致优先**：同一种含义只有一种表现；所有按键共用一个网格、一套颜色、一种按下反馈。
2. **颜色只表示状态**：模块不能自选颜色，只能声明状态，颜色由设计系统统一决定。装饰性颜色一律不用。
3. **为像素设计**：控台按键是 64×64、1:1 点对点显示，所有尺寸、位置以整像素为单位。
4. **成体系，不打补丁**：遇到问题先找规则层面的原因，改规则而不是单点修补；改完写进本文件。
5. **所有变化都要过渡**：灯光不允许瞬间切换（见"灯光"）；按键上的动画全部用同一条曲线（见"动画"）。

## 控台按键

### 画布

- 按键图 64×64 JPEG，在 480×272 的屏上 1:1 显示，图外是一圈黑色窗口（2026-10-24 用 1 像素棋盘格实拍确认）。
- 屏幕能看到 RGB 子像素：1 像素宽的线会带彩边，图形线条不细于 2 像素。

### 按键屏布局（`M18Layout`、`KeyField`）

15 个键是同一块连通屏幕上的窗口。实测（2026-10-29，`dock-probe keywindows`）：

| 项 | 值 | 依据 |
|---|---|---|
| 键距（横、竖） | **96 px** | 网格照片里三个键窗口边的错位相同 → 键距是 4 的倍数；尺子照片量出 96.5 ± 1 → 只能是 96。480 = 5 × 96 |
| 两张按键图之间 | 32 px（半个键） | 96 − 64 |
| 窗口 | 约 73 px 见方，按键图居中，每边多露约 4.5 px 黑边 | 微距照片按子像素数 |
| 按键场 | 448 × 256，1 号键左上角为原点 | (5 − 1) × 96 + 64，(3 − 1) × 96 + 64 |

- **规则：跨键运动画在按键场上**（`KeyField`），连同间隔一起，再切成 15 张 64×64。图形在键和间隔里速度一样，经过间隔时被面板挡住，看起来是在一块屏上连续移动；把键当作挨着排（旧做法）会一格一格跳，速度忽快忽慢（`dock-probe keyglide` 最后一段对比）。
- **只能画在按键图上**：窗口里那圈黑边属于背景层。背景图（`setBackgroundImage`）一上传，控台有时会断开 USB 1–2 秒再重连，像是把图存进了闪存，所以背景层不能做动画，保持黑色。
- **没有跨键垂直同步**：按键图逐张上传、逐张显示，同一帧里两个键的更新可能差一两帧，固件没有"整屏一起换"的指令。用户看过后接受。
- 测量方法：先试过逐像素移动背景图对齐，因背景上传会掉线而放弃；改为每键显示尺子（白底、每 8 px 一条黑线）拍整面板求键距，再用"背景和按键图都画每 4 px 一条线"的网格拍微距，看窗口边上线条是否连续。

### 动画（`Motion`）

全产品用同一个缓动公式：三次贝塞尔 **(a, 0, 1 − a, 1)**，起步缓、中段快、结尾缓，只有一个参数——中段峰值是平均速度的 peak 倍，a = 1 − 1/peak（`Motion.Curve`）。按键像 OLED 小屏动画引擎那样陡（peak 5），灯带整条换色要柔和（peak 1.5，正好就是 smoothstep 3t² − 2t³）。2026-10-29 在灯带上并排比较 peak 1.5 / 2.5 / 5（`dock-probe lightease`），用户选原来的 1.5。

| 工具 | 规则 |
|---|---|
| `Motion.light` | peak 1.5，(1/3, 0, 2/3, 1)：灯带所有交叉淡变（切场景、翻页换灯效、提醒亮灭、断线重连淡入、退出淡出、活动指示、编程助手提醒的过渡） |
| `Motion.ease`（`Motion.keys`） | peak 5，三次贝塞尔 **(0.8, 0, 0.2, 1)**：前后各五分之一时间只走约 5%，中段峰值是平均速度的 **5 倍**。所有从一个状态到另一个状态的变化都用它。起初用 (0.7, 0, 0.3, 1)，峰值 3.3 倍，用户看额度动画后认为中段不够快，改为现值 |
| `Motion.settle` | 带回弹的到位：冲过约 8% 再回来（迪士尼原则里的跟随、弹性）。**只用在封面键长按触发时弹回**：其他键触发时会反色铺满，没有"冲过头"的空间；数值、按下、环一律不用 |
| `Motion.stretch` | 挤压拉伸：形状移动越快沿运动方向越长、面积不变，最快时长 30% |
| `Motion.duration(distance:)` | 图形移动：走一个键宽 0.25 s，随距离平方根增长，0.18–0.6 s |
| `Motion.duration(change:)` | 数值变化（占量程的比例）：小变化 0.35 s，全量程 0.7 s，长到看得出变了 |
| `ValueTransitions` | 数值从屏幕上当前显示的值出发、按 `ease` 滑到新值，进行中 60 帧重绘，到位即停 |

- 例外：长按进度本身匀速走，让 1 秒读起来就是 1 秒。
- 帧率、按时间而不是按帧数计算，与灯带相同（`FrameGrid`，60 Hz）。
- **翻页**（`PageSlide`）：旧页滑走、新页隔一个键距跟进来，在按键场上连续移动，0.3 s、60 帧、`Motion.ease`。换场景（按另一个圆键）**横向**：去右边的圆键从右边进来，去左边的从左边进来，和圆键的左右位置一致；同场景翻页（重复按同一圆键）**纵向**，新页从下面推上来，页在同一场景里上下叠放。单页场景不动。从按下圆键起到滑动接手，以及滑动期间，其他重绘一律暂停（否则新页会先闪一帧），落定后全画质重绘。
- **翻页带动态模糊**：中段每帧移动超过一个键距，每帧按 360° 快门（整帧时间）把多个瞬间叠加平均，约每 3 px 一次采样、最多 16 次；起步和收尾慢，几乎不糊，中段拉成拖影，跳变连成运动。2026-10-29 实物对比不模糊 / 180° / 360°，用户选 360°。代价：每帧平均 4 ms、最慢 9 ms（预算 16.7 ms），整次翻页发送量与不模糊相同（约 358 KB）。模糊帧的 JPEG 比清晰帧大（渐变多），只因为只有中段几帧才不影响总量。
- 演示：`dock-probe keyease`（匀速对比、缓动、挤压拉伸、落地回弹、弹出）。演示和 App 都要用 release 构建：调试版画一帧带图标的按键约 150 ms，release 约 2 ms。

### 内容

每个按键只有这几样东西：**图标**（SF Symbols）或**数值**（数字或短词）、可选的**标签**，或者**整幅封面**。
模块用 `KeyFace` 描述：`symbol` / `title`（数值）/ `caption`（标签）/ `artwork` / `tone`。

### 网格

| 项 | 规格 |
|---|---|
| 底色 | 纯黑 `#000000` |
| 边距 | 四周 8 px |
| 标签 | 系统字体 Medium 11 px，字距 +0.5 px，基线固定在 y = 55（所有按键一致，Latin 与 CJK 同基线），宽度上限 56 px，超出自动缩小 |
| 图标框 | 无标签 36×36，有标签 28×28；外框尺寸与位置取整像素 |
| 数值 | SF Rounded Semibold 23 px，字距 −0.3 px，宽度上限 50 px |
| 图标 / 数值与标签间距 | ≥ 6 px |
| 垂直位置 | 按实际笔画（不是字体框）定位：无标签时在边距内居中；有标签时与标签成组，剩余高度按 3:1 分在上、下 |

### 状态与颜色（`KeyTone`）

| 状态 | 用途 | 底色 | 图标 / 数值 | 标签 |
|---|---|---|---|---|
| `normal` | 普通操作 | 黑 | 白 `#FFFFFF` | 灰 `#8E8E93` |
| `dim` | 当前不可用 | 黑 | 深灰 `#4A4A4E` | `#3E3E42` |
| `on` | 开关处于开启（设备开、当前场景、已喜爱、显示中的来源） | 白 | 黑 | `#3A3A3C` |
| `alert` | 录制中、已静音、危险操作 | 红 `#FF3B30` | 白 | `#FFD7D4` |
| `live` | 推流中 | 绿 `#30D158` | 黑 | `#0B3D1A` |
| `caution` | 等用户继续（录制暂停、工作室预览） | 琥珀 `#FF9F0A` | 黑 | `#4A2C00` |

- 状态底色**铺满整键，无圆角**。
- 红、绿、琥珀与灯带含义一致：录制红、推流绿、暂停琥珀。

### 额度键（`KeyMeter`）

服务额度用整键作进度条，是"颜色只表示状态"之外唯一的例外：颜色代表服务本身，不代表状态。

- **填充表示剩余**：从左往右按剩余比例填满整列像素（`round(剩余 × 64)` 列，边缘不做混色）；用完就是全黑。数值显示剩余百分比（`83%`），标签说明窗口（`5h`、`Week`）。
- **服务色**：取各自应用图标的主色——Claude `#E4643F`、Codex `#576EFE`（2026-10-25 从图标取样）。只用在填充上。M18 屏幕会把颜色洗淡，柔和的品牌色（如 `#D97757`）在控台上发灰，所以用图标里饱和的那一档。
- **文字随底色分色**：同一个数值或标签被填充边缘切开时，填充上的部分用黑色（标签用服务色压暗到 35%），黑底上的部分照常用白色（标签灰色）。按列裁切，像素级对齐。
- 额度键不叠加状态色；没有数据时显示 `—` 和 `dim` 状态。
- **打开应用的键也铺满整键**，不在键里放带圆角的图标：把图标上的图形抠出来（与图标底板颜色差距足够大的像素，边缘按底板反混色），放大 1.2 倍铺在整键底色上（`IconGlyph`）。Claude 底色就是服务色 `#E4643F`、白色星芒；Codex 白底、蓝色云团（取 ChatGPT.app 包内的 `icon-codex-light.png`，因为 Codex 装在 ChatGPT.app 里，应用图标是 ChatGPT 的）。只读图标中间 68%，避开底板的圆角边和高光；颜色差门槛高于底板自身的上下渐变。

### 按下与长按

一套语言：**普通键按下、长按触发都是"反色"，封面不变色、只缩放**。

| 情况 | 普通按键 | 封面（App 图标、专辑封面） |
|---|---|---|
| 按下（短按键） | 从边缘往里翻成反色：每块底色和它上面的字互换（黑底白字 → 白底黑字，绿底黑字 → 黑底绿字，红底白字 → 白底红字，额度填充 → 黑底服务色字）；手指挡住中间，边缘最先变、一眼看到 | 往里缩 5 px，露出黑边 |
| 长按：按住 | 不反色。环从键外出现、收进来，然后从 12 点顺时针匀速走一圈 | 和环同一时钟往里缩（每帧对齐） |
| 长按：满 1 秒触发 | 从环的位置同时向内、向外扩成反色，盖满整键（包括外面那圈），再淡回 | 带回弹（`settle`）弹回原大小，环淡出 |
| 长按：中途松手 | 环从停下的位置退回键外 | 跟着环恢复 |
| 触发后仍按着 | 保持原样，直到松手（`DockController.firedKeys`） | 同左 |

- 时长：按下、环收进、环退出都是 `KeyDesign.pressTime` = **0.2 s**，按 `Motion.ease`；同一常数保证封面缩放与环同步。触发响应 0.35 s（前 45% 扩散，后面淡回）。
- 环：3 px 宽，最终离边缘 2 px（浅色键上环外留一圈原底色），用**按键自己的字色**画——正是触发反色后的底色，所以环与反色是一条规则；额度键填充上的一段用黑色；封面没有字色，逐像素取黑或白中反差大的一个。
- 所有长按键都用 `KeyHold`（息屏、PC 插座断电、退出 Apple Music）：`phase` 依次为 `.holding` → `.confirmed`（只在动作确实执行时） / `.released`。触发后松手不打断响应。
- 每秒 60 帧、固定时间格（`FrameGrid`），与按键屏刷新率一致。同一个键既有短按又有长按时，短按在**松手**时执行，长按触发后松手不再执行短按。
- 按键屏刷新与带宽（实测，作为所有按键动画的约束）：
  - 屏幕刷新约 60 Hz（2026-10-25，`dock-probe fpstest`，慢动作视频逐帧数序号）。**按键动画帧率必须整除 60**（60、30、20…），否则帧停留时长不均，看起来忽快忽慢。
  - 一帧 JPEG 约 2.3–3.3 KB；控台不回确认，厂商库先排队，传输上限只能从外面看。15 键各 60 帧连发时整屏约 600–700 张/秒，超出的在队列里积压。分配规则：**同时在动的键数 × 帧率 ≤ 450 张/秒**——1–7 个键 60 帧，8–15 个键 30 帧，由控制器统一降帧。
  - **大面积动画用低画质，静止帧用全画质**（2026-10-29）：多键同时运动的帧用 JPEG 质量 `KeyRenderer.motionQuality`（0.6），动画落定的那一帧一律全画质。一键一帧从约 1.1 KB 降到约 0.9 KB，正好装进一个约 1 KB 的 USB 包（全画质要两个），发送量约减半；运动中的色边模糊看不出来。上面 600–700 张/秒是按 2.3–3.3 KB 的图测的，小图明显更多。翻页 15 键 × 60 帧 × 0.3 s 用低画质实测流畅（`dock-probe slidetest`）；30 帧时慢且经过间隔的键会闪。
- 演示：`dock-probe pressdemo`、`dock-probe holddemo`；离线预览 `dock-probe holdsheet <out.png> [封面图]`、`dock-probe keysheet <out.png> --pressed`。

### 数值

- **原地变化**：数值用等宽数字（tabular figures），横向按排版宽度居中、纵向按大写字母高度放在固定基线（y = 40）上，不按实际笔画定位。55 → 52 → 54 只有数字本身在变，不左右、上下跳（以前按笔画居中，"1" 窄、"8" 宽，整串会挪）。图标仍按笔画居中。
- **额度等读数用缓动**：新读数从当前显示值按 `ease` 滑过去，数字和填充一起走；第一次读数从空填满（`ValueTransitions`，`AIQuotaModule.gauges`）。演示：`dock-probe quotademo`、`dock-probe digitdemo`。

### 文案

- **标签用英文**：11 px 的中文笔画会糊在一起，英文清晰。
- 用短词，首字母大写，尽量不超过 10 个字符：`Volume` `Brightness` `Sleep` `Mic` `Muted` `Loved` `Record` `Recording` `Pause` `Resume` `Stream` `Live` `Studio` `Transition` `Replay` `Save` `Saved` `Camera`。
- 通用状态词：`On` / `Off` / `Offline` / `Unknown` / `Unset` / `Failed` / `Retry`。
- **处理中不换标签**：命令发出到确认之间保留原标签（设备名、`Love` 等），按下时的变暗已经表示按到了；只有结果才替换标签（`Failed`、`Sent`、`Retry`）。曾用 `…` 表示处理中，它会盖掉设备名、看起来像文字被截断，2026-10-25 起不再使用（截断过长名字的 `…` 不是状态词）。
- 数值不带单位符号时由标签说明含义（`45` + `Volume`）；温度、百分比、功率保留符号（`26°`、`40%`、`86W`）。
- 功率：1000 W 以下取整瓦（`86W`），以上用 kW 保留一位小数（`1.5kW`）。
- 带功率计量的开关开启时，用读数代替图标（`on` 状态不变）；关闭或读数不可用时显示图标。
- 用户自己起的名字（HA 实体名、OBS 场景 / 来源名）原样显示，不做自动翻译；按键名称在设置里填英文短名，同一设备的按键用同一个名字（`A/C`、`Fan`、`Light Bar`、`PC`），由图标区分功能。设置窗口里有此提示。
- 错误详情放在设置窗口，按键上只显示 `Failed`。

### 渲染与编码

- 图标和文字以 4 倍分辨率绘制，精确缩小到 64×64，再提高边缘对比度去掉灰边。
- JPEG 质量 1.0（全色度）。低于 1.0 时 ImageIO 会做 4:2:0 色度子采样，彩色边缘糊成 2×2 色块。

### 新增按键检查

1. 选一个 SF Symbol（在 36 / 28 px 下仍能认出），或者用数值；
2. 声明状态（`KeyTone`），不要写颜色；
3. 标签按上面的文案规则；
4. 用 `dock-probe keysheet <out.png> [封面图]` 出预览，必要时 `--pressed` 看按下状态；
5. 在控台实物上确认。

| 长按触发"整键反色闪光"从环往里长 | 外面 2 px 的边没被盖到；改为从环同时向内向外扩散 |
| 长按触发"环退回外面" | 与中途松手的样子相同，分不清成功和取消 |
| 按下也反色、长按触发再反色 | 两种含义撞在一起；反色留给短按和长按触发，长按键按住时只有环 |

## 灯光

细节与参数见 [rhythm.md](rhythm.md) 和 [progress.md](progress.md) 的"灯光最终规则"，原则如下：

- **一切变化都有缓动**，由灯光引擎统一保证，模块无法绕过。
- **感知亮度**：所有亮度在感知空间计算，最后只做一次 Gamma 2.2 映射；暗部有防抖。
- **灯珠的位置按实测四角算**（`M18Layout.corners`，`dock-probe ledcorners` 用圆键把亮点移到每个角上校准）：前后边各 6 颗、左右边各 5 颗，每条边内均匀排开。凡是按"左右 / 前后"分的灯效都按灯珠的实际坐标分，不按序号分——例如 OBS 同时录制和直播时，红绿按灯珠在中线左右分，分界落在 5/6 和 16/17 之间（2026-10-27，按序号分时前后分界错开了半颗，看起来不在正中）。
- **场景各管各的灯**：灯带只显示当前场景的东西；别的场景的状态和提醒不会出现（例如 OBS 录制灯只在通用控制场景亮）。
- **优先级**（场景内）：通知 > 活动状态（OBS 输出）> 当前页动画（音乐）> 场景底色。
- **颜色语义与按键一致**：录制红 `#FF0000`、推流绿 `#00FF00`、暂停琥珀 `#FF9C00`。
- **灯带 60 Hz**：灯带本身跟得上更高的帧率，60 Hz 是设计选择（与按键屏一致），不是灯带的上限。
  - 实测（2026-10-25，`dock-probe ledwalk` + `ledscan`）：一颗灯每帧走一格，iPhone 240 帧慢动作原片按时间戳逐帧读出灯带实际显示的帧。30 / 60 / 120 / 240 Hz 下分别显示了 52/52、98/98、195/196、266/268 个位置（只看得到的 9 颗灯；相机漏帧处看不清的步不计），即灯带基本收到一帧显示一帧，至少到 240 Hz；零星 1–2 帧在识别阈值附近，不呈规律。主机端四档都按时发出、USB 无跳帧（单次写入中位 0.1 ms，最长约 9 ms）。240 Hz 已到相机极限，更高未测。
  - 更早的 `ledfps`（全亮/全灭翻转、肉眼看慢动作）得出"90 和 120 跟不上"，已被上面的逐帧测量推翻：翻转图案看不出显示了哪一帧，不能用来测刷新率（该命令已删除）。
  - 测量要用原片（隔空投送选"所有照片数据"）：相册导出的成片把慢放做进时间里，头尾加速段还会丢帧，`ledscan` 会按标记长度检查并警告。
  - 灯光引擎和所有灯效（包括音乐律动）都按 60 帧、固定时间格出帧（`FrameGrid`，与按键动画共用）：某帧晚了不拖后面的帧，卡顿后跳到下一格、不连发补帧。灯效的动态一律按经过的时间计算，不按帧数，帧率变化不改变速度。
- **颜色代码在灯带上和屏幕上一致**：颜色先按 sRGB 解码成线性光再取灯珠比例（`LightPixel`），亮度另按感知亮度走伽马 2.2。2026-10-25 之前颜色代码被直接当成灯珠比例，小通道被放大几倍（含白色成分的颜色偏粉紫、橙色偏黄），当时对着灯带调出的颜色都已换算成新代码（`RGB.fromRawLEDProportions`，灯带上的样子不变；设置里保存的自定义场景色在升级后第一次启动时换算一次）。旧代码 → 新代码：VibeCoding `#85FC5E` → `#BEFCA2`，合成器 `#FF5700` → `#FF9E00`，OBS 暂停 `#FF5500` → `#FF9C00`，Codex 提醒 `#3048FF` → `#7891FF`，Claude 提醒 `#FF2400` → `#FF6900`；纯色不变。仍以灯带实物为准：灯珠的颜色和屏幕不会完全一样，新颜色还是要对着灯带确认。音乐律动一直走 OKLab，本来就是线性光，不受影响。
- **场景底色**（设置里可改）：

| 场景 | 默认色 | 灯带观感 |
|---|---|---|
| 通用控制 | `#FFFFFF` | 白 |
| VibeCoding | `#BEFCA2` | 黄绿（2026-10-25 用户在灯带上调定；与 Codex 蓝、Claude 橙拉开距离，灯带提醒用应用色） |
| 合成器 | `#FF9E00` | 橙（2026-10-25 用户在灯带上调定） |

- **音乐灯效追求柔和精致**（参照 HomePod 顶部灯光）：滤色叠加、临界阻尼包络、OKLab 混色。灯带当作正方形底座上的二维画布：白底上漂着封面的其他颜色，主题色是盖在上面的大光团；只有低频动光团——贝斯在弹就一直聚着、底鼓再收紧，把主色收小、拉向边缘，同时压暗、加浓（"收"）；中频在边上原地提亮、扩散（"放"），不碰光团——有低频时提亮是饱和的原色相，没有时重的提亮闪白；除光团运动外，所有效果都在原地发生，任何时候都不出现单颗孤立的颜色，也不突然换色。细节见 [rhythm.md](rhythm.md)。

### 编程助手提醒（VibeCoding，`AgentLight`）

Codex 和 Claude 的任务状态只做在灯带上，不占按键。2026-10-25 在灯带上逐条演示、按用户反馈定下：

- **颜色 = 是谁，动态 = 什么状态，亮度和速度 = 多急。** 状态不用另外的颜色，都用应用自己的灯带色：Codex `#7891FF`、Claude `#FF6900`（对着灯带调定）。场景底色黄绿 `#BEFCA2`，和两种应用色拉开距离。
- **三档强度**：强提醒（召唤；完成、出错那一刻）亮点满亮 1.0、灯环底光 0.4；环境（巡航）光点 0.8、底光 0.25；弱提醒（静候 0.7、故障保持 0.65、召唤弱版 0.7）。提醒灯效始终算活动状态，不被灯光引擎减半。
- **暗处不丢颜色**：灯亮着时，颜色里占 2% 以上的通道换算成 8 位后最少留 1 级，不会因为取整变成 0——否则暗的浅色只剩纯色相，比原意饱和得多（2026-10-27）；纯色本来没有的通道仍然是 0。
- **长亮不低于 0.25**：太暗时导光条不再把灯珠的光混开，一颗颗灯珠就显出来了。只有一闪而过的凹陷可以更暗。
- **不显颗粒**：灯带上移动的亮点至少覆盖约 3 颗灯：亮芯、前方约 1.6 颗灯的柔和边缘、后方逐渐变暗的长尾巴。
- **一切亮度变化都缓降缓升**，包括"故障"闪烁：它是两次平滑的凹陷，不是亮灭切换。生硬的亮灭在 60 Hz 下熄灭帧数忽多忽少，看起来像丢帧；不规则的间隔也被看成卡顿。亮点出现时从周围亮度淡入，不凭空跳亮。
- **强版和弱版是同一条曲线**：整个周期按比例划分（亮起、行进、汇合、间歇），弱版只是放慢、调暗，不含固定秒数（固定秒数曾让强版的光点跑到两侧才亮起、弱版先停住再走）。唯一的区别是弱版召唤不让短灯条跟着闪。
- **动态**：
  | 状态 | 名字 | 灯效 |
  |---|---|---|
  | 工作中 | 巡航 | 光点带长尾巴逆时针绕环，3 秒一圈，匀速 |
  | 完成那一刻 | 合拢 | 光点加速、尾巴拉长到铺满整圈，满亮一下，缓降到静候 |
  | 完成、等你查看 | 静候 | 整圈静止，6 秒一次很轻的呼吸 |
  | 出错那一刻 | 故障 | 光点停住并膨胀成满亮整圈，两次凹陷，缓降到故障保持 |
  | 出错、等你查看 | 故障保持 | 整圈常亮，每 1.5 秒同样的两次凹陷，像一盏快坏的灯 |
  | 等你批准或回答 | 召唤 | 两道光在前方正中（离人最近）亮起，以平均速度 0.6 倍的初速出发（亮足时只走出约 1.5 颗灯，不停顿），沿两侧加速，到后方减速汇合并亮一下，1.4 秒一次；短灯条在汇合时同步亮 |
  | 同上，但应用在前台 | 召唤弱版 | 同一条曲线放慢到 3 秒一次，更暗，短灯条不闪 |
  | 空闲、打断、你已查看 | — | 1.2 秒淡回场景底色；你主动打断时不放过场 |
- **你在看就不吵**：应用在前台时召唤降为弱版；完成时只放合拢，直接淡回底色。
- **状态只靠明确信号结束，不用超时**：长时间没有事件仍显示工作中。
- **两个应用同时有状态**（不分左右半圈）：
  - 都在工作：两颗光点同时绕环，相隔半圈，各用自己的颜色；尾巴缩短，两个亮区之间留出暗区，每颗灯按两颗光点各自贡献的亮度混色，换色只发生在暗区（在亮头上硬切换色会显得卡顿）。
  - 都在召唤：一次一个应用轮流，换色在汇合闪光淡去后的最后四分之一周期里渐变。
  - 都在等你查看（静候或故障保持）：每 3 秒换一个应用，1 秒渐变。
  - 级别不同：更急的占整个灯环，另一个应用用自己的颜色以 0.5 点亮两根短灯条。
  - 优先级：召唤 > 完成、出错那一刻 > 故障保持 > 静候 > 巡航 > 空闲。
- 演示：`dock-probe agentlight [codex|claude|both] [步骤…]`，按一个应用（或两个应用同时）的完整故事逐步播放并念出场景；`--sheet <out.png>` 离线出图。`dock-probe ledbench` 检查灯带是否丢帧（2026-10-25 实测 60 帧下 0 丢帧）。测灯带刷新率用 `dock-probe ledwalk`（拍 240 帧慢动作原片）+ `dock-probe ledscan <视频>`，见上面“灯带 60 Hz”。

## 工具

- `dock-probe keysheet <out.png> [封面图] [--pressed]`：通用控制三页和 VibeCoding 额度页的按键预览（像素放大 3 倍）。
- `dock-probe holdsheet <out.png> [封面图]`：三种长按键在环收进、半圈、满圈和触发响应时的样子。
- 实物演示（都用 release 构建）：`keyglide`（跨键滑动）、`keyease`（统一曲线）、`pressdemo`（按下）、`holddemo`（长按）、`quotademo`（额度缓动）、`digitdemo`（数字原地变化）。
- `dock-probe slidetest [帧率] [画质] [秒]`：翻页实测，并打印各画质下一帧的字节数。`dock-probe lightease`：灯带三种曲线对比。
- `dock-probe keywindows [--seam]`：按键屏布局标定，每键显示尺子（或背景与按键图同一网格）供拍照测量。
- `dock-probe keytest [秒数]`：第一排显示像素测试图（条纹、棋盘格、边框），检查 1:1 显示。
- `CPA_KEY=… dock-probe cpa <地址>`：只读查看 CPA 的账号列表和 Claude / Codex 额度接口的原始返回（邮箱打码）。

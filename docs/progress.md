| 1 | 音量 − | 静音 / 音量 | 音量 + | 输出切换 | 输入切换 |
| 2 | 亮度 − | 当前亮度 | 亮度 + | 长按关屏 | 麦克风静音 |
| 3 | 上一首 | 播放 / 暂停 | 下一首 | 当前封面 | Apple Music 喜爱 |

- 音量短按调整 2%，长按 400 ms 后重复并逐渐加速；系统接口不可调的显示器输出走 DDC。
- 输入、输出在勾选且在线的候选设备中轮换，按 UID 保存选择；设置使用复选框，勾选不改变当前路由，也不表示同时播放。
- 麦克风静音优先硬件 mute，否则保存并归零输入增益；失败时显示错误，不冒充会议软件的独立静音状态。
- 关屏要求持续按住 1 秒；松手、翻页、切场景取消。已修复早期“松手一秒后仍关屏”的问题。
- 媒体仅控制 Apple Music。封面键短按在 Music 中显示当前曲目（松手时执行），按住 1 秒退出 Music（统一的长按环；Music 未运行时没有长按）。封面沿用现有取图路径；喜爱使用 `favorited`，用曲目 persistent ID 避免切歌期间误操作。
- 移除打拍按键，离线节奏分析工具保留。用户已确认第一页完成。

## 第 2 页：智能家居

当前本机已保存的布局：

| 排 | 第 1 键 | 第 2 键 | 第 3 键 | 第 4 键 | 第 5 键 |
|---|---|---|---|---|---|
| 1 | 空调开关 | 降温 | 升温 | 空调模式 | PC 插座 |
| 2 | 风扇开关 | 减速 | 加速 | 摇头 | 风型 |
| 3 | 挂灯开关 | 调暗 | 调亮 | 暖一点 | 冷一点 |

- 目标为现有空调、落地扇、米家显示器挂灯和 PC 插座。每键可在设置中更改功能、实体与名称；另支持场景、脚本、窗帘和只读状态。
- 每排主开关键开启时显示一次温度 / 风速 / 亮度，关闭时显示电源图标；加减键显示 − / +，避免两列重复数值。
- 调温遵守设备步长及上下限，风速遵守档位，灯光色温以 Kelvin 调整并限制范围。不支持或不可用的操作置灰。
- HA WebSocket 订阅真实状态，初始快照与事件合并，断线清空旧状态、重连不重放操作；访问令牌按服务器地址隔离存入 macOS 钥匙串。
- **PC 插座正在给服务器供电，用户明确禁止实物测试。** `safePower` 要求持续长按 1 秒才发送明确的 `turn_off`；提前松手、翻页、断线、绑定变化取消。断电时短按只发送 `turn_on`。整个配置过程未向真实插座或其他家电发送控制命令，长按验证仅使用本地模拟 `switch.plug`。
- 开关类按键（`safePower`、开关切换、打开、关闭，设备为 `switch`）在开启时显示实时功率：通过 HA 实体登记表（`config/entity_registry/list_for_display`）找到同一设备上单位为 W / kW 的传感器，设置里可改选其他传感器或不显示；读数随 HA 状态事件更新，快慢取决于插座上报频率。只读取，不发送任何命令。WebSocket 单条消息上限提高到 16 MB，避免大型家庭的状态快照超出默认 1 MB。2026-10-25 用户确认控台上 PC 插座已显示实时功率。
- 实机读取确认：空调 `current_humidity` 没有数值；独立湿度传感器存在但状态未知。目标湿度只是设置项，不能用作实际湿度。DJI Romo 当前也返回未知状态，未加入主控页。
- 配置前旧绑定曾备份到本机临时目录；临时文件不作为长期恢复保障，也不随仓库提交。

## 第 3 页：本机 OBS

- 第一排：录制 / 暂停录制 / 推流 / 工作室模式 / 转场。
- 第二排：五个场景；第三排：两个音频静音 / 两个来源显隐 / 保存回放。
- 每键可改目标与动作，支持回放缓存、虚拟相机及已注册热键。工作室模式先选预览场景，再转场；普通模式直接切节目场景。
- 仅连接本机 OBS，读取 OBS 现有 WebSocket 端口及认证配置，不另存密码；请求超时、断线重连，不重放失败操作。
- 状态由 OBS 事件直接更新：按键操作后不回读 OBS，状态以 OBS 推送的事件为准；只有列表变化时重读对应部分；某部分 10 秒内没有任何事件或读取时才兜底核对，刚有事件的部分不会被落后的查询结果覆盖。读取期间到达的事件不会被旧回包覆盖（有回归测试）。
- 未连接界面在中间一排第 2–4 列横向居中，显示打开 OBS / 状态 / 重连。
- 实机曾读取到 1 个场景、4 个音频源、3 个顶层来源和 55 个热键。用户最初反馈按键无反应；加入诊断并重启后确认可用，日志记录按键 → ToggleRecord → 成功。此前根因未确定，不标记为已定位。

## 灯光最终规则

- 所有灯效由 LightEngine 统一处理感知亮度：模块提供浮点颜色比例和亮度，用户设置 × 活动倍率 × 像素亮度合并后仅做一次 Gamma 2.2 映射，最后量化并做暗部防抖。
- 硬件 LED 总亮度固定 100%，实际调光合入输出帧。非活动感知亮度为用户设置的 50%，活动为 100%，约 0.6 秒过渡；满设置时半亮对应约 55/255 驱动。
- 优先级：通知 > OBS 输出 > 当前页音乐 > 场景底色。OBS 随应用启动跟踪，在通用控制场景内跨页持续显示，切到其他场景不显示（2026-10-25 起场景灯光互相隔离）；通知结束后恢复原状态。
- OBS 录制纯红 `#FF0000`、推流纯绿 `#00FF00`，**2 秒一轮，感知亮度 50–100%**。同时进行时左红右绿；暂停录制为橙琥珀 `#FF9C00` 常亮，推流半边仍呼吸。
- 用户确认灯珠排列：0–10 下半圈、11–21 上半圈，逆时针。灯珠坐标按实测四角（2.5 / 8.5 / 13.5 / 19.5，`dock-probe ledcorners`）：前后边各 6 颗、左右边各 5 颗；OBS 左红右绿按灯珠实际左右位置分，分界在 5/6 与 16/17 之间；两根短灯条仍左红右绿（位置在律动可视化里对称拖定后固定：宽度 0.21 / 0.79、离前边 0.17）。
- 音乐律动（2026-10-27 定稿，细节见 [rhythm.md](rhythm.md)）：白底 + 封面其他颜色像洗牌一样轮流换到前面 + 主题色大光团；只有低频牵引主色光团向边缘收（贝斯在弹就持续聚拢，底鼓再收紧）、压暗 50%、加浓；中频分轻重——重击提亮扩散（无低频时闪白、有低频时饱和），轻击只是更饱和地润一下；高频只在低中频安静时闪清脆单点；相邻灯珠颜色差 ≤ 0.1（高频闪点除外），输出饱和度上限 85%。菜单栏面板"律动"按钮打开律动可视化窗口。
- 音乐暂停算活动状态，不叠加非活动减半；光环在播放时最低底光（感知 0.40，满设置约 34/255）附近慢呼吸，短灯条对齐其播放最低值（0.35），暂停即无声，响度相关效果随之归零。OBS 遮盖音乐时音频分析继续，仅保留最近 0.25 秒待消费事件，避免恢复时积压。

## 屏幕联动与设置界面

- 跟随电脑屏幕休眠关闭控制器屏幕和灯带，暂停输出，唤醒后恢复当前页面、设置亮度及最新灯效；休眠期间的后台更新不会重亮，设备重连遵守休眠状态。
- 控制器任意键可请求唤醒屏幕；第一次按键的整个按下 / 松开周期只用于唤醒，再按才执行功能。对唤醒通知早于 USB 按键的情况也有保护，不绕过锁屏。
- 休眠会释放已按下的键，取消已有长按操作。整机深睡能否被控制器唤醒取决于 USB 和系统支持，不能仅靠应用保证。
- 原生 Settings 窗口顶部为通用 / 场景 / 音频 / 智能家居 / OBS 五个面板，记住上次位置，支持 Command–Comma。菜单栏“设置”按用户要求去除省略号。
- 设备信息、亮度、权限归通用，场景色独立配置，音频候选设备使用复选框；HA 提供 3×5 按键选择网格和实体搜索。

## VibeCoding 场景（开发中，2026-10-25）

- 场景色 `#BEFCA2`（用户在灯带上调定，避开两个应用色）。三排都已完成。任务状态提醒只做在灯带上：灯效（单个应用和两个应用同时）已在灯带上逐条演示定稿（见 design.md「编程助手提醒」）。
- 提醒接入（2026-10-25）：`AgentMonitor` 随应用启动，按会话记录状态（`AgentStatus`，只靠明确信号结束，不用超时），`AgentGlow` 每帧按灯效语言渲染并只放进 VibeCoding 场景的灯光。来源只有两个（用户决定不读取两边的会话记录）：hook 事件（`dock-hook` 经 `~/Library/Application Support/StreamDock/agent.sock` 转给应用，只保留应用、事件名、会话编号、通知类型，丢掉消息正文和工具参数；不输出、总是返回 0、1 秒内退出，应用没运行时直接退出），以及系统告知的前台应用（查看即清除提醒、召唤降为弱版）和应用退出。两处 hook 覆盖不到的情况：Codex 申请联网等权限走 `request_permissions` 工具、不触发批准 hook，由工具名为 `request_permissions` 的 `PreToolUse` 识别（转发程序只转发工具名，不看工具参数；2026-10-25 实测确认），之后的 `PostToolUse` 表示已答复；Claude 被打断、或拒绝一个批准请求（拒绝即结束这一轮），都不发任何 hook：从控台按 Stop 时，控台程序直接把 Claude 最近有动静的那一轮收回空闲；在 Claude 里直接用键盘 Esc 或鼠标打断、拒绝时没有任何信号，灯带保持原状，直到下一条消息（用户接受这个限制，不为此监听键盘）。`idle_prompt`（等你输入）仍然接着：终端里的 Claude Code 可能会发，收到时把仍显示工作中或召唤的会话收回空闲；但 2026-10-25 实测 Claude 桌面应用打断后两分半钟都没有发出它。Claude 桌面应用弹批准提示时触发的是 `Notification` 的 `permission_prompt`（有时也有 `PermissionRequest`），两者都接了。
- 设置 → VibeCoding → 灯带提醒：显示是否在接收、两边最近的事件；Claude、Codex 的 hook 各自加载、还原；两边共用一个事件转发程序 `dock-hook`，放在最前面，可安装或移除，加载 hook 时也会自动安装，应用启动时更新到最新版（移除前先还原两边的 hook，否则它们会报找不到命令）。加载只合并本程序的条目，还原只删除本程序的条目（凭命令里的 `StreamDock/dock-hook` 识别），每次写入前备份原文件到 `~/Library/Application Support/StreamDock/backups/`。Codex 的新 hook 要在命令行 `/hooks` 里信任一次。`dock-probe hookpreview` 打印加载会写入的内容，不写文件。hook 超时统一 2 秒（Codex 对 Interrupt、SessionEnd 限 3 秒）；设置按当前版本逐条比对，旧配置显示"需要更新"。
- 2026-10-25 灯带颜色改为先按 sRGB 解码再取灯珠比例，颜色代码在灯带上和屏幕上一致；已调好的颜色换算成新代码，灯带上的样子不变（见 design.md 灯光一节）。
- **额度来源 CPA**（CLIProxyAPI，自建服务器，远程管理已开启）：两个账号的登录凭据挂在 CPA 上，本机客户端不开也能更新。流程：`GET /v0/management/auth-files` 取账号 → 每个服务一次 `POST /v0/management/api-call`，由 CPA 用该账号的令牌（`$TOKEN$`）发固定的 GET：
  - Claude：`https://api.anthropic.com/api/oauth/usage`（`five_hour` / `seven_day` 的 `utilization`、`resets_at`）；
  - Codex：`https://chatgpt.com/backend-api/wham/usage`（`rate_limit` 的两个窗口按 `limit_window_seconds` 区分 5h / 周、`credits.balance`、`rate_limit_reset_credits.available_count`）。
  - 这两个上游接口没有公开文档，字段以 2026-10-25 的实测为准（`dock-probe cpa`）。
- 安全：管理密钥只存钥匙串、只走 HTTPS（本机地址除外）；只发上述查询，不调用消耗重置卡、删除或上传凭据的接口（有测试约束）。
- 上游没有推送，只在 VibeCoding 场景显示时查询，切走即停，不在后台刷新。每个服务的读数缓存 5 分钟（从上次查询算起，失败也算）：切入场景时只查询已过期的服务，5 分钟内反复切换只用缓存、不发请求；停留在场景里则在到期时自动再查。人为刷新不看缓存：按某一排的额度键只刷新这一排的服务，在设置里点"立即刷新"刷新两者，改地址或换账号也会立即查询。查询失败时保留上一次读数，设置窗口显示原因。
- 按键：Codex 排 打开 | 5h | Week | Resets | Credits；Claude 排 打开 | 5h | Week | 5h 重置倒计时 | 周重置倒计时（Claude 没有重置卡，超额用量未开启）。额度键按剩余比例用服务色填充，规则见 [design.md](design.md)"额度键"。
- CPA 中有 1 个 Claude、2 个 Codex 账号；Codex 排用 Plus 账号（与本机 Codex 同一账号），在设置的 VibeCoding 页可改。
- 第 3 排：Accept | Stop | New | Send | Voice，只对前台的 Codex（ChatGPT.app，`com.openai.codex`）或 Claude 桌面应用（`com.anthropic.claudefordesktop`）生效，前台是其他应用时变暗、不发送。快捷键取自两个应用包内（2026-10-25）：Codex 命令表 Approve request = Enter、Decline request = Escape、新对话 ⌘⇧O；Claude 菜单 New = ⌘N；Send 两边都是 Enter；Accept 在 Codex 是 Enter，在 Claude 是 ⌘↩（Claude 的权限提示上标的就是 ⌘↩，单按 Enter 无效，2026-10-25 实测）。Voice 按住期间保持 Fn 按下，交给用户的输入法（微信输入法）语音识别。需要「辅助功能」权限（设置的权限一节）。2026-10-25 实测：两个应用里前台判断、New、Send、Stop（Esc 能打断生成）、Voice（合成的 Fn 能触发微信输入法）均正常；Accept 在 Claude（⌘↩）和 Codex（Enter）里都能批准。Codex 的 Esc 要按两次才停止（第一次只是准备停止，按钮变成 ESC 提示，这是它防误触的设计），所以控台的 Stop 在 Codex 正在工作（灯带巡航）时连发两次 Esc（间隔 0.15 秒），按一下就停；Codex 在等批准时只发一次，即拒绝这个请求，不能再跟第二个；Codex 空闲或前台是 Claude 时也只发一次。是否在工作取自灯带提醒的状态。
- 任务状态提醒计划只做在灯带上（不占按键），依赖本机客户端（Claude Code hooks、Codex 会话记录），只在 VibeCoding 场景显示。

## 已知限制与后续方向

- 纯远端 AirPlay（不勾选本机）没有可供当前 Core Audio 采集的本机输出，只剩专辑配色的光团慢慢漂，无法提供真实节奏；本机和远端组合播放已恢复。详见 [rhythm.md](rhythm.md)。
- VibeCoding 第 3 排（任务状态、提醒、快捷键）以及合成器场景仍待开发。
- 底鼓与贝斯不区分：低频的起音（贝斯换音也算）都是低频打击；中频不分军鼓与人声起音，靠"重击"排名挑出明显的那些。速度偶尔跳到一倍或一半，只影响重击"每半拍最多一个"的间隔。
- 底鼓会带出中频提亮：底鼓的上半身（150–400 Hz）和击槌的"咔"（2–5 kHz）都在中频里，和军鼓的鼓身、响弦同一处，
  大小也和军鼓差不多（7 首歌里与低频打击同时出现的中频提亮，大小中位数 0.71–0.87，单独出现的 0.56–0.94），
  同时还常伴着踩镲 → 按频段、子频段、大小、有没有高频都分不开（`dock-probe midorigin <trace>` 可查）。
  以前的底鼓 / 军鼓联动识别逐下只分对六成，还让底鼓晚 40 ms，已去掉；要分开得靠更细的音色或拍位判断，暂不做（2026-10-28）。
- 设备固件版本号在当前设备上可能返回空字符串。
- 按时间自动夜间降亮暂不做。
- 曾遇到 Apple Music 切歌后清空播放列表、不开始播放；退出 StreamDock 后也出现，之后自行恢复，尚无证据归因于本应用。

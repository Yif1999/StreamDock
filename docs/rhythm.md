# 节奏识别系统（RhythmKit）

把「音乐」App 的声音变成灯光能用的节奏事件。整体参照实时节拍跟踪的成熟做法：
起音检测函数（onset detection function）→ 自相关 + 梳状模板测速度 → 累计得分（Ellis 2007 /
BTrack 一类）跟踪拍点 → 显式状态机决定是否输出节拍。渲染层只消费事件，不做任何判断。

```
音频（「音乐」进程，~10ms 一块）
  │
  ▼ ① FeatureExtractor（音频线程，帧率 ≈ 94 Hz）
  │    FFT 1024 / hop 512，Hann 窗；对数压缩 Y=log(1+γ|X|)
  │    三个频段的谱通量 F_b = Σ max(0, Y_t − Y_{t−1})：低 30–150 Hz、中 150–6000 Hz、高 6000–16000 Hz（首尾相接）
  │    每个频段用自己的长期均值归一化（AdaptiveScale，τ=10 s，启动阶段做偏差校正）→ flux，用来"找打击"
  │    另算线性幅度上的谱通量 rawFlux（不压缩、不归一化），随真实音量变化，用来"定大小"
  │    （对数通量与音量无关——音量降到 30% 它几乎不变，所以不能拿来判断一下有多响）
  │    起音函数 O = 1.0·低 + 0.8·中 + 0.5·高；另输出各频段响度（AdaptiveScale 峰值，半衰期 50 s）
  │
  ▼ ② RhythmAnalyzer（同一线程，逐帧）
  │    ├ PeakPicker：每个频段找"打击"——局部极大（±3 帧）、高于最近 1 s 均值 + 1.5σ、
  │    │    且至少是该频段长期均值的 2 倍；同频段至少间隔 80 ms（高频 120 ms）；确认需看后 3 帧（约 32 ms 延迟）
  │    ├ TempoEstimator：每 0.5 s 对最近 6 s 的 O 做自相关 A(τ)；
  │    │    梳状得分 S(τ)=Σ_{m=1..4} A(mτ)/m，乘以速度先验 P(τ)=exp(−½(log₂(τ/0.5s)/0.9)²)
  │    │    → 速度 τ*、周期性置信度 c = 标准（有偏）自相关 r(τ*) = Σx_t·x_{t−τ}/Σx_t²
  │    ├ BeatTracker：累计得分 C(t)=(1−α)O(t)+α·max_v W(t−v)C(v)，W 为以 τ* 为中心的对数高斯，α=0.9
  │    │    每拍过半时向前推演 C，预测下一拍时间 T（提前给出，渲染可以让峰值正好落在 T）
  │    ├ SalienceDetector（重击）：全程只用一个量——这一击的"大小"：
  │    │    每个频段的打击 = 它的 rawFlux ÷ 该频段最近 60 s 打击 rawFlux 的第 90 百分位
  │    │    （底鼓和底鼓比、军鼓和军鼓比；两个频段的原始量级差十倍，不能直接相加）；
  │    │    40 ms 内的低频+中频打击合为一击，大小 = 1.0·低 + 0.8·中（底鼓是人感到的重拍）；
  │    │    是不是重击：在最近 8 s 的击打里按大小排名，前 30% 即是，一达标立刻报告；
  │    │    有多重：大小 ÷ 最近 60 s 击打大小的第 90 百分位 → 0…1，安静段的重击自然更小；
  │    │    与拍点网格无关：切分、加花的重击照样算；
  │    │    每半拍最多一个（速度未知时 0.25 s），间隔内只放行更大的一下，弱的不会挡住强的
  │    └ 状态机（带回滞）：
  │         平缓    —— 节奏活跃度 a < 0.3 持续 1.5 s：不出拍、不出闪烁，只剩颜色缓慢变换
  │         寻拍    —— a ≥ 0.45 但置信度不足：只有重击，没有网格拍
  │         锁定    —— 置信度 ≥ 0.25 连续两次：重击 + 预测的网格拍；置信度 < 0.12 持续 3 s 退回寻拍
  │         活跃度 a = 最近 2 s 低/中频打击强度之和 ÷ 最近 60 s 内这个和的第 75 百分位
  │         （没有打击的平缓段自然为 0；用起音函数均值不行——它已按长期均值归一化，恒在常数附近）
  │         强度 intensity = smoothstep((a−0.3)/0.4)，1 s 平滑；缩放一切视觉效果
  │
  ▼ 事件（带时间戳，跨线程队列）
       底鼓还是军鼓（StrikeSorter，通用规则、不针对某首歌）：40 ms 内的低频和中频打击算同一下；
              两个频段各自和本频段最近 60 s 大击打的第 90 百分位比，这一下在哪个频段更突出就归哪类——
              底鼓在低频里突出，它的"咔"声在中频里只算普通；军鼓在中频里突出，漏到低频的部分只算普通；
              一样突出（同时敲）算军鼓；只有一个频段的就归那个频段。判定在这一下开始后 40 ms 给出。
              （先前的规则"中频够大就算军鼓"把带响亮"咔"声的底鼓也当成军鼓，反过来底鼓优先又吞掉军鼓，2026-10-27）
       .kick(time, strength)：最重的底鼓（KickDetector：判为底鼓的打击按 8 s 内低频大小排名前 30%，每半拍最多一个）
       .lift(time, band: mid/high, strength)：判为军鼓的打击（mid），或高频打击（high），大小对比本频段自己的大击打
       .accent、.expectedBeat、.hit：重击、网格拍和全部打击，只供 rhythm-eval 对照，灯光不用
       快照：state、tempo、intensity、各频段响度，以及 lowDraw——
              低频（底鼓 + 贝斯）的"抽电"程度 0…1（LowDraw）：低频能量在最近 6 s 里的位置，
              第 20 百分位为 0、第 95 百分位为 1，跨度至少是顶部的 35%：持续的低音铺底回落到 0，
              只有冒出来的底鼓、换音的贝斯才"抽电"

  ▼ ③ MusicGlow（渲染，60 fps）——亮度、颜色、速度的分配统一在 GlowBudget（2026-10-27 参照 HomePod Sound Glow 重做）
       单位：所有亮度都是"感知亮度" 0…1，只在最后由 DockCore.LEDOutput 换算成 LED 驱动值（伽马 2.2）、暗部防抖；
              闪光一律用"滤色" screen(a,b) = 1 − (1−a)(1−b) 叠加：永远不超过 1，新的一下一定看得见
       画布（2026-10-27 参照 HomePod 的二维光团重做）：底座是正方形，从上往下看当作一块画布，每颗灯显示它所在位置的画布颜色。
              灯的位置（M18Layout.position）：22 颗环灯沿四边均匀分布（每边 5.5 颗，拐角落在两颗之间），从左边中点往下逆时针——
              0 在左边中点偏下、5 在前边正中、10/11 在右边中点两侧、16 在后边正中、21 在左边中点偏上；
              短灯条 22、23 是圆键两侧的横条（按实物照片：中心在宽度 0.17 / 0.83、离前边 0.22，长 0.12），取色沿灯条长度平均；
              底座实测约 1.1 宽 : 1 深，按正方形处理
       分工：底鼓"踢"光团、"收"——压暗、加浓；军鼓是"放"——提亮、扩散；高音只在鼓停下时闪点。
              军鼓优先：提亮时压住低频的收紧（最多压掉 80%），同时落下的底鼓不会把军鼓抵消
       底色与光团：主题色铺满画布；封面的每种颜色（最多 4 种，都参与）和一个伴色（封面里的白，没有就是带主题色调的白，
              占 15%）各是一个羽化光团（高斯，软边放宽 1.4 倍），半径 √(0.7·占比/π)，至少 0.3（软边约覆盖 5 颗灯，不会只染一颗）；
              颜色在 OKLab 里混（底色权重 0.45，补回 60% 混合损失的彩度；两色相互抵消时少补——色相相反的颜色各占一半时
              平均接近灰、色相转得很快，补回彩度会让一颗灯突然翻色）。每颗灯跟随画布的颜色变化每秒不超过 1.2（OKLab 距离），
              光团被踢得再快，灯也是渐变过去（2026-10-27：光团边缘偏硬、混色有翻转点，光团经过时单颗灯突然变色）。光团靠近哪条边，那一段灯就染上它的颜色——
              整圈不会一起转，变化都是局部的。亮度 = 0.55 − 0.1·intensity ± 0.08·响度；彩度平时用 85%
       光团运动：每个光团沿一个缓慢转向的方向轻推（0.08 + 0.12·intensity），彼此靠近会互相推开，离边 0.12 处有软墙，
              中心不出画布（离边至少 0.04：越过拐角会只染拐角那一颗）；阻尼 0.9 s、限速 1.5。
              重底鼓"踢"光团：在边上选一个新位置（统一换位规则），把离它最近的光团朝那里踢（0.9·强度），
              光团冲到边上，那一段染上它的颜色，再被阻尼慢下来——颜色变化跟着底鼓走，没有底鼓时光团慢慢漂
       统一换位规则（MusicGlow.place）：底鼓的目标、中音提亮、高音闪点都在边上随机的新位置（固定种子，同样的音乐出同样的灯），
              避开本频段此刻还亮着的位置
       低频收紧（底鼓 + 贝斯）："收"——lowDraw × 深度（0.35 + 0.65·intensity）× 1.6，两级平滑（收 0.08 s、放 0.45 s，再 0.1 s）；
              光团缩小（最多一半），整体压暗 30%，颜色加浓："加浓"是朝这个颜色在灯珠上最鲜艳的样子靠（同色相、去掉白的成分），
              最多 70%，所以封面上的淡色也看得出变浓；接近白、看不出色相的颜色朝主题色最鲜艳的样子靠。
              松开时回弹并略微越过平时：保留收紧峰值、0.7 s 放开的跟随量，高出当前收紧的部分让光团大 30%、
              颜色再加浓 40%、亮度略升，然后回到平时（HomePod 的"回到中央、放大一些"）
       中音提亮（判为军鼓的打击，见上方"底鼓还是军鼓"）："放"——在边上的新位置原地沿环扩散，
              颜色变亮、彩度略加（20%）；重的一下在峰值处往白偏（提亮超过 0.65 后渐入，满提亮时 30% 往白；70%、45% 实看都偏强，2026-10-27）——
              克制的、饱和度低而亮度高的闪白；一般的军鼓保持自己的颜色；离它最近的光团同时胀大（最多 60%）；
              大小 (0.25 + 0.75·强度)·intensity，范围 0.1 + 0.65·强度²（圈），重的铺满整圈；≈0.1 s 亮起、≈0.6 s 降一半
       高音闪点（镲片、踩镲）：只在低中频安静时出现——距上一个重底鼓或中音提亮 0.6 s 以上、低频收紧 < 0.15；
              在边上的新位置点亮 1–2 颗灯，短促清脆（0.025 s 亮起、0.18 s 衰减），往伴色的白偏一半；
              大小 (0.5 + 0.5·强度)·intensity，两次至少隔 0.09 s，不落在还亮着的闪点 0.12 圈以内
       短灯条：显示画布在它们位置的颜色（光团经过时变色）；底光 0.35 + 0.15·响度·intensity，随收紧轻微下沉，随中音提亮点亮
       响度（0.35 s）、intensity（0.6 s）先平滑再参与任何计算
       调试：测试里可以只开其中一种效果（MusicGlowLayer），逐个检查；光团在任何模式下都照常被底鼓踢（实测调参时曾放在设置里，调完已移除）
       暂停：0.8 s 内收成暗的慢呼吸（6 s 一次），光团几乎停住；继续播放 0.4 s 亮回；
              Music 停止或退出 2.5 s 后才回到场景色（切歌时会短暂报告"停止"，不会闪）
       切歌：光团留在原地，颜色在约 2.5 s 里换成新专辑的；节奏不重来
       （旧版的网格拍整圈脉动、低频重击扩散爆白、单独的高频闪烁点已去掉：网格拍改由收紧与提亮的一收一放承担，
        扩散移给中音提亮，爆白先改成提亮时主题色更饱和，后来又把闪白加回给重的军鼓——一般的军鼓看到更多主题色，重的才闪白；
        第一版试过的重底鼓白热核心也已去掉；旧的闪烁点改成高音闪点；整圈流动先改成原地换色，再改成二维画布上的光团）

  封面取色（ArtworkPalette）：如实取色，灯带显示封面本来有的颜色——
       用 OKLab 彩度（≥ 0.04）判断像素有没有颜色，不用 HSV 饱和度（它把暗像素算得很鲜艳）；
       按面积计数，只有无彩色的暗像素（黑）不算，深绿、深蓝这类有彩色的暗像素照常算；
       一种色相要占封面 5% 以上才入选，最多 4 种，取这些像素的平均色原样使用：
       不提彩度、不挪明度、不补封面没有的相邻色相；
       无彩色部分占 30% 以上时加一个带封面色调的白，完全无彩色的封面就是这种白；
       只有一种颜色时补一个同色相、淡一些的颜色，让流光有对比（占 30%）；
       每种颜色带着它在封面上的面积占比（Swatch.share），灯带按占比分配渐变里的长度
       （2026-10-25 改：旧规则先按 HSV 挑色再强制提彩度，灰白封面会被染成饱和蓝）
```

### 2026-10-27 灯带实看调整（新版律动）

逐条在灯带上看、按用户反馈改，每条都是规则层面的改动：

- 网格拍整圈脉动去掉；低频重击的扩散爆白改给中音（重音时要"看到更多主题色"，不是白）；重底鼓白热核心试过后去掉。
- 一下底鼓同时落进低频和中频，收紧和提亮互相抵消 → 与低频打击相差 40 ms 内的中频打击归底鼓。
- 高音做成"小号的中音提亮"时和中音分不开、几乎看不到 → 改成闪点；闪点在鼓声下太多太乱 → 只在低中频安静时出现。
- 流动一直显得慢、快慢看不出 → 基础速度 4 倍（后来整体降回约 2.7 倍，0.16 圈/秒）、涌动加大到 2.5、缓动 0.5 s；intensity 在流行歌里几乎恒满，快慢改由底鼓密度决定。
- 只有颜色流动：亮结跟着颜色走会强化流动感、闪点选在流动的辅助色段会"转圈"、提亮让颜色变宽会推移整圈边界、
  中音提亮推高流速会把颜色推走 → 收拢点、提亮、闪点一律原地发生；只有底鼓推流速；测试 effectsStayInPlace 锁住这条。
- 流动的渐变不要了 → 先改成色块原地换色（底鼓推动）；随机换一组颜色显得生硬 → 改成二维画布：光团在正方形底座上漂、
  被底鼓踢向边缘，灯显示画布在它位置的颜色；收紧点也随之换成光团缩小。任何时候都不许出现孤立的单颗颜色
  （测试 noLoneLEDs：四色封面、每 0.5 s 踢一次，逐帧检查一分钟；曾因光团越过拐角只染拐角一颗而失败，现在光团中心不出画布）。
- 光团经过时单颗灯突然变色 → 混色在相反色相处会翻转、光团边缘偏硬 → 少补抵消处的彩度、光团羽化、每颗灯限速渐变
  （测试 ledsNeverSwitchColorAtOnce、oppositeHuesBlendSmoothly）。
- 收紧位置一直不变（等低频完全松开才换，可低音几乎不停）→ 每个重底鼓换位，三个频段统一用同一条换位规则。
- 收紧像整圈变暗、又一闪一闪 → 先改为几何收窄 + 两级平滑；再发现大幅变暗和中音提亮互相抵消、显得乱 →
  低频改成"压暗 + 加浓"，中音以亮度为主；压暗 5% 太亮、45% 太暗，定在 30%；
  按比例放大彩度看不出加浓 → 改为朝颜色最鲜艳的样子靠。
- 分频对比（`bandcompare`，《月亮不打烊》200 s，119.95 BPM）：建议的"2–6k 与 150–400 同时起音算军鼓"和现在的中频
  150–2500 识别出的军鼓重合约 77%、都落在第 2 拍，没有明显更好 → 军鼓保持现在的分频；高频 2.5–11k 的落点和军鼓重叠
  （混进了响弦），6k 以上则落在反拍、像踩镲 → 高频改为 6–16 kHz。随后中频也延到 6 kHz、和高频接上：
  中间空出的 2.5–6 kHz 正是军鼓"啪"声和响弦所在，不算进中频时军鼓显得不突出、容易被判成底鼓。只看 30–150 的起音会把贝斯换音也算进去，
  底鼓仍用重底鼓识别。
- 提亮从不往白偏后闪白几乎看不到，可惜了那种克制的高亮 → 提亮整体加亮（0.25 + 0.75·强度），重的军鼓在峰值处往白偏
  （测试 heavySnaresFlashWhite）。
- 很多军鼓被同时落下的底鼓吞掉 → 识别上大的中频打击算军鼓、优先于底鼓；灯光上提亮时压住收紧。
- 底鼓也被当成军鼓、只会发亮；改成底鼓优先又吞掉军鼓 → 不再用固定的优先顺序，改为通用规则：
  每一下按它在哪个频段更突出来判（StrikeSorter；测试 strikesSortByWhereTheyStandOut：响亮"咔"声的底鼓和厚鼓身的军鼓各归其类）。

## 设计约束

- **唯一的打击来源**：所有"这里有一下"的判断都来自 PeakPicker，渲染层不再自己看电平跳变。
- **唯一的自适应机制**：所有归一化都用 `AdaptiveScale`，时间常数写在一个地方。
- **分析与渲染解耦**：分析跑在音频帧率上，事件带时间戳；渲染帧率不影响识别精度。
- **可回放**：特征帧（不是音频）可以录成文本，`dock-probe rhythm-replay` 离线重跑 ②，
  不保存任何可还原音乐的数据。录制：在通用控制场景播放时 `defaults write dev.yif.StreamDock rhythmTraceSeconds -float 200`
  （写成文字也认），文件在 App 的临时目录 `streamdock-rhythm-trace.txt`。除三个频段外还记 5 个细分频段
  （30–150、150–400、400–2k、2–6k、6–16k Hz 的变化量，`FeatureExtractor.detailEdges`，只供离线研究），
  开头记下歌名和录制开始时播到第几秒，结果里的时间能换算成歌曲时间。
- **可比较分频**：`dock-probe bandcompare <trace>` 对比实时分析的分频（中频当军鼓）和建议的分频
  （2–6k 与 150–400 同时起音才算军鼓、6k 以上算镲片）识别出的底鼓、军鼓、镲片，按每 10 s 列出（歌曲时间）。
- **可对照**：录制时可在 M18 上按键打拍子，`dock-probe rhythm-eval` 计算与打拍的 F 值
  （±70 ms 容差，MIREX 惯例）。打拍只是**参考**：人打拍有延迟、不准，不作为标准答案，
  也不按它调参数；算法以信号本身的分析（录制数据、合成测试）为准。
- **可测试**：`RhythmKitTests` 用合成信号检验速度、拍点、状态切换。

## 打拍对照记录（仅供参考）

2026-10-24，用一首歌 200 s 的录制，听者在每个乐段按"感受最强的鼓点"打拍（166 下）：

| 作为"强拍"的事件 | F（±70 ms） | 精确率 | 召回率 |
|---|---|---|---|
| 网格拍（BPM + 相位） | 0.32 | 0.24 | 0.47 |
| 重击（本设计） | **0.62** | 0.51 | 0.78 |

结论：人感受到的强拍是"最突出的那几下打击"，不一定落在拍点网格上；网格只适合做底层律动。
重击参数在窗口 4–16 s、比例 25–35% 之间都在 0.60–0.62，是一个平台而不是尖峰，不是对这首歌过拟合。

已知问题：这首歌 150 s、170 s 附近速度跳到 173 / 77 BPM。网格现在只驱动柔和脉动，影响小；
后续可把 TempoEstimator 换成 HMM（速度为隐状态、相邻时刻速度连续）来根治。

### 开头频闪（2026-10-24）

现象：歌曲开头整条灯快速一亮一暗。录制开头 40 s 分析：重击每秒 2 次左右，每次都亮到 ≥50%，
间隙又几乎全黑（为了对比度）。根因是"有多重"完全用相对量衡量——重击挑选是 8 s 内排名，
大小也是排名，而底层 flux 本身又按 10 s 均值归一化、还是对数压缩的，安静段的打击看起来和
响亮段一样大。修正：引入线性幅度的 rawFlux，重击大小对比最近 60 s 的大击打（测试
`quietPassageAccentsAreSmallerThroughTheWholePipeline` 用真实合成音频验证）。

### 底鼓被当成轻拍（2026-10-24）

现象：有些段落底鼓不怎么亮。录制 60 s 分析：最响的 25% 低频打击（大底鼓）只有 38% 成为重击。
根因是"是不是重击"和"有多重"用了两把尺子：排名用对数、按均值归一化的 flux，它衡量的是
"多突然"而不是"多重"——低频一直有贝斯，底鼓显得不突然（≈8），军鼓在中频显得很突然（≈11），
于是排名选中军鼓；而按线性 rawFlux 算大小，军鼓只有底鼓的十分之一，结果是暗淡的重击占了
位置，还在半拍间隔内挡住了后面的底鼓。修正：排名和大小统一成一个量——各频段 rawFlux 对比
本频段自己的大击打。同一段录音大底鼓成为重击的比例 38% → 69%；剩下的都在底鼓很密的段落
（每 0.3 s 一下），8 s 内只取前 30% 是有意的。测试 `kicksAreAccentsNotLightBeats` 复现了
这个模式（旧算法失败、新算法通过）。打拍对照只作参考，不据此调参。

### 重击被吞、亮度无统一分配（2026-10-24）

旧渲染：亮度 = 0.32 + 0.22·响度·… + 0.8·脉冲，再截断到 1；新重击的目标若低于当前正在衰减的
脉冲就直接丢弃。同一段 60 s 录音里 30% 的重击看不出亮度变化。改为 GlowBudget：各层按比例、
滤色叠加，重击包络每次都升到 screen(当前, 大小)。重击可见（短灯条亮度上升 > 0.08）70% → 85%，
剩下的都在平缓段（按设计不闪）或强度刚起来时。测试：`ControlModulesTests/GlowLevelsTests`。

### 渲染的"土嗨感"（2026-10-24）

现象：重击亮灭太快、不柔和；流光时快时慢、频繁换向，灯珠高频闪烁。原因：重击是 40 ms 硬升 +
0.28 s 半衰；每个低/中频打击都给光团速度加一脚，还有概率直接反向；响度逐帧直接驱动亮度和宽度；
闪烁点一阶跟随、起步有拐角。修正见上方 ③：统一的临界阻尼包络、只加减速不换向的流光、平滑响度。
同一段 60 s 录音对比：每颗灯珠明暗换向 2.71 → 0.86 次/秒，单帧跳变 P99 0.144 → 0.071、
最大 0.56 → 0.23，重击可见率不变（82%）。测试 `flashIsSmooth` 检验包络形状。

### 光效品味（2026-10-24）

感知亮度 + 伽马输出 + 暗部防抖；OKLab 混色 + 峰值偏白；重击从一点扩散（重的铺满、轻的局部）；
封面配色在 OKLCh 里整理；暂停收成慢呼吸、停止才回场景色、切歌颜色渐变。同一段录音对比
（按感知亮度）：平滑度、亮度分布与上一版一致；局部亮起的重击 20 → 29 / 60。
测试：`GlowColorTests`、`PauseTests`。

### AirPlay / 组合播放采集（2026-10-24）

实测组合播放时，`com.apple.Music` 的音频进程输出设备为空，而
`com.apple.AirPlayXPCHelper` 在向本机显示器音频设备输出。只采集 Music 会得到静音。
采集现在每 2 秒检查 Music 的 AirPlay 状态及实际音频路由：Music 仍有输出时保留原来源；
仅当 Music 确认启用 AirPlay 且自身无输出时，改采集正在输出的 AirPlay 系统助手。
这是系统共享的 AirPlay 渲染进程，不能进一步按发送应用拆分；不使用全系统音频或麦克风作为回退。
进程、输出设备或默认输出变化时重建 tap；回调停止超过 5 秒也会重试。
聚合设备只包含 tap，避免混入物理设备的输入通道；无信号时维持配色流光。
纯远端播放没有本机可采集的输出时保留配色流光；没有本机输出的路由不因缺少回调反复重建。

实测验证：20:22:46 从 Music（进程对象 187）切换至 AirPlay 助手（176），
20:22:48 起持续收到 `signal=true`，节奏分析重新进入寻拍/锁定；本机播放与组合播放均已验证。

纯远端实测：取消本机播放后，Music 与 AirPlay 助手的输出设备列表均为空。
20:25 直接采集助手（176）仍没有音频回调与信号，因此现有 Core Audio tap 路径
不能为该模式提供真实律动；组合播放可用。没有自动更改用户的 AirPlay 设备选择。

### 活动亮度与 OBS 覆盖（2026-10-24）

音乐播放使用设置亮度，暂停慢呼吸使用设置亮度的一半。音乐输出未映射的浮点 LightPixel；此倍率与用户亮度由 LightEngine 合并，在最后的 LEDOutput 中仅做一次 Gamma 2.2 映射和暗部防抖。硬件总亮度固定 100%，不改变 GlowBudget 的感知亮度计算。OBS 录制/推流指示优先于音乐，通知优先于 OBS；覆盖期间音频分析继续，但只保留最近 0.25 秒的待消费节奏事件，避免积压与恢复时的旧事件突发。
